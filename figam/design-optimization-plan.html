设计现状评估

当前设计体系的优势与待优化点

Assessment

✓ 已建立的设计优势

  • 视觉语言统一：旧纸、蜡封、墨色、玫瑰色形成完整叙事氛围
  • 信息架构清晰：四级页面层级覆盖9个功能域，逻辑自洽
  • 编辑器三栏结构：工具-画布-属性的专业布局，扩展性强
  • 计划组件体系：年/月/周/日/清单的3-in-1设计，数据联动思路清晰
  • 真实信件模板：18种风格覆盖从古至今，差异化显著
  • 移动端考虑：底部工具栏、属性抽屉、简洁模式已有雏形

△ 待深化的优化方向

  • 功能密度过高：支线功能（日记/手账/待寄）与核心写信体验权重模糊
  • 交互细节缺失：拆信动画、组件内嵌编辑、拖拽吸附等关键交互未细化
  • 状态反馈不足：自动保存、同步状态、加载、错误等反馈体系不完整
  • 模板整合路径：18种真实信件模板如何接入编辑器流程尚不清晰
  • 数据安全流程：备份导入导出、草稿恢复的完整用户旅程待补全
  • 动效规范缺失：各场景过渡动画、微交互缺乏统一标准

六个关键模块的具体设计改进

Details
01

编辑器体验深化

三栏布局的交互细节与创作流畅度优化

创作流畅度

  • 操作栈管理：50步撤销/重做，文字编辑、元素移动、属性修改统一入栈
  • 智能辅助线：拖拽时显示中心线、边距线，靠近8px阈值自动吸附
  • 层级操作：右键菜单 + 属性面板双通道，支持置顶/置底/上移/下移
  • 键盘快捷键：Ctrl+Z/Y撤销重做，Ctrl+[/]调整层级，空格拖拽画布

组件内嵌编辑

  • 双击进入：计划组件双击进入内部编辑模式，画布灰显，组件高亮
  • 数据同步：组件修改实时同步到手账系统，右上角显示"已同步"状态
  • 尺寸自适应：组件支持拖拽缩放，内部布局自动响应调整
  • 透明背景：一键切换组件背景透明，融入信纸不突兀

自动保存与草稿

  • 保存状态可见：顶部栏实时显示"已保存 / 保存中 / 未连接"
  • 版本回溯：保留最近5个自动保存版本，可一键回退
  • 离开提醒：未保存时关闭页面，弹出草稿确认弹窗
  • 断点续编：再次打开自动恢复上次编辑位置与选中状态

真实信件模板接入

  • 模板应用入口：信纸样式选择器扩展为18种真实模板预览
  • 自动排版：选择模板后自动转换文字方向（横排/竖排）、字体栈
  • 参数可调：污渍程度、折痕样式、纸张年代可微调
  • 导出保真：导出PNG时完整保留纸纹、印章、邮戳等材质层
02

阅读与拆信仪式感

从信封到内容的沉浸式体验设计

拆信动画流程

  • 蜡封裂开：点击信封后蜡封先出现裂纹，0.3s后分两半向两侧滑落
  • 信封翻盖：上盖向上翻开，带纸张轻响音效（用户触发后播放）
  • 信纸抽出：信纸从信封中缓缓滑出，同时背景柔和变暗聚焦内容
  • 可跳过机制：第二次查看同一封信自动跳过动画，直接进入阅读

语音气泡交互

  • 浮出时机：拆信动画结束后，语音气泡从右下角淡入上浮
  • 点击播放：必须用户主动点击才播放，规避浏览器自动播放限制
  • 智能续播：本会话已授权音频后，后续信件可自动淡入播放
  • BGM混音：语音播放时BGM自动降至15%音量，结束后淡回

分页阅读体验

  • 翻页动效：左右滑动或点击翻页，带纸张翻动的卷曲效果
  • 进度感知：底部显示页码与阅读进度条，支持点击跳转
  • 书签功能：长按段落可添加书签，下次打开自动定位
  • 回信入口：阅读到底部浮现"写回信"按钮，预填充收信人

阅读上下文面板

  • 信件元信息：右侧固定显示收信人、日期、状态、所属信箱
  • 故事线入口：关联的日记章节、手账记录快捷跳转
  • 操作区：编辑、导出、回信、删除四个核心操作
  • 移动端：收起为底部浮动按钮组，上滑展开完整面板
03

信箱系统与慢递体验

把等待设计成产品体验的一部分

信箱装饰系统

  • 信箱单元化：每个信箱作为独立可装饰单元，外壳+贴纸+标签+状态
  • 材质主题：铜制邮筒、木质信盒、牛皮档案袋、航空信封四种基础材质
  • 装饰元素：蜡封章、手写标签、邮戳、照片夹、捆扎绳等可组合装饰
  • 状态可视化：未读信件数量通过信箱插旗、突出标签等方式呈现

双人信箱与投递

  • 投递中状态：寄出后信件进入"在途"状态，显示预计送达时间
  • 随机慢递：支持平邮（3-7天）、慢递（1-3月）、半年期三种模式
  • 离线补送达：离线期间到达的信件，下次启动时统一"派件"提示
  • 加密投递包：无后端场景下，导出加密文件手动交换信件

待寄与定时发送

  • 待寄列表：独立入口展示所有待寄出信件，支持修改与取消
  • 定时设置：指定日期时间发送，支持农历、纪念日提醒预设
  • 寄出仪式：点击"寄出"后有信封投入信箱的动画与音效
  • 撤回窗口：寄出后10分钟内可撤回，模拟"还在邮筒里"的状态

信件堆叠浏览

  • 堆叠交互：左右滑动切换信件，当前信件放大居中，两侧露出预览
  • 时间线导航：底部时间轴快速跳转到某月/某年的信件
  • 筛选分组：按未读、待回信、带录音、有照片等维度筛选
  • 双视角切换：双人信箱支持"他的信/我的信/全部"三视图切换
04

计划组件与手账闭环

从独立功能到信纸可嵌入组件的统一体系

年度计划 3-in-1

  • YEAR视图：12个月色块总览，颜色标记任务类别，点击月份进入月计划
  • NOTE视图：年度目标、季度复盘、关键事件的自由笔记区
  • LIST视图：年度愿望清单、读书清单、观影清单等可自定义列表
  • 类别系统：日常/工作/成长/重点四种类别，颜色全局统一

月/周/日联动

  • 逐级下钻：年→月→周→日，点击日期自动跳转对应层级视图
  • 任务同步：任一视图添加的任务，在其他视图自动同步显示状态
  • 复盘体系：月末/周末自动生成复盘入口，回顾完成情况
  • 农历支持：月视图显示农历日期，传统节日自动标注

信纸嵌入机制

  • 组件库入口：编辑器左侧组件栏统一管理，拖拽即可插入信纸
  • 尺寸预设：提供窄版、宽版、方形三种预设尺寸，也可自由缩放
  • 样式适配：组件自动适应当前信纸风格（复古/简约/夜间）
  • 导出完整：导出图片时组件作为信纸一部分完整渲染

手账与写信联动

  • 一键同步：写完信后可选择"同步到手账"，自动记录今日通信
  • 日记关联：信件可关联对应日记章节，阅读时侧边栏显示入口
  • 手账搜索：全局搜索覆盖手账内容，可按关键词、日期、标签检索
  • 模板系统：手账页面支持应用模板，快速搭建版式结构
05

数据安全与备份体系

给高情感价值内容足够的安全感

自动草稿机制

  • 定时保存：编辑器每25秒自动保存一次草稿到IndexedDB
  • 多版本保留：每封信保留最近5个历史版本，可查看时间戳
  • 恢复入口：重新打开编辑页时，顶部弹出"恢复上次草稿"提示
  • 冲突处理：多端编辑冲突时展示版本对比，由用户选择保留

备份与导出

  • 全量备份：一键导出所有信箱、信件、手账、媒体文件
  • 可选加密：支持设置密码加密备份文件，AES加密保障隐私
  • 媒体选项：可选择是否包含录音、图片等媒体资源（减小体积）
  • 增量备份：后续备份仅导出新增/修改内容，提升效率

导入与恢复

  • 预览摘要：导入前先展示备份内容摘要（信箱数、信件数、日期）
  • 合并模式：支持"合并到现有"和"覆盖全部"两种导入模式
  • 进度反馈：导入过程显示进度条和当前处理项，避免焦虑
  • 失败回滚：导入异常时自动回滚，不破坏现有数据

存储与兼容

  • IndexedDB迁移：大资源（录音、图片）从localStorage迁移到IndexedDB
  • 容量提示：存储空间使用接近上限时提前预警
  • 格式降级：录音格式根据浏览器支持自动选择webm/m4a
  • 数据版本：数据库带版本号，升级时自动执行迁移脚本
06

移动端与简洁模式

小屏体验优化与轻量化使用场景

移动端编辑器

  • 全屏画布：移动端编辑器默认全屏显示信纸，工具收到底部
  • 底部工具栏：文字/图片/语音/组件四个核心工具，大尺寸按钮
  • 属性抽屉：属性设置从底部上滑弹出，不挤压画布空间
  • 手势支持：双指缩放画布、单指拖拽元素、双击编辑文字

简洁模式

  • 核心功能：仅保留收信、写信两个核心入口，隐藏支线功能
  • 导航简化：底部Tab只保留"信箱"和"写信"两项
  • 可随时切换：设置中一键切换完整模式/简洁模式，记忆偏好
  • 渐进解锁：首次使用默认简洁模式，使用深度增加后提示解锁完整功能

首次引导

  • 分步引导：不做一次性长教程，在对应功能首次使用时轻量提示
  • 示例信箱：首次进入预置一个示例信箱，包含3封演示信件
  • 创建引导：新建第一封信时，分步引导添加文字、图片、录音
  • 可跳过：所有引导都可一键跳过，不强迫用户走完流程

全局搜索与标签

  • 统一搜索：顶部搜索框覆盖信件、信箱、日记、手账全部内容
  • 结果分组：搜索结果按类型分组展示，点击直接跳转对应位置
  • 标签系统：信件支持打标签（未读/待回/重要/自定义）
  • 筛选组合：标签+信箱+时间范围可组合筛选，高效定位

技术落地建议

前端架构与实现层面的关键考量

Technical

数据层架构

  • 使用 IndexedDB 存储大资源（录音、图片、备份）
  • localStorage 仅存配置与轻量状态，避免容量超限
  • 数据库带 schemaVersion，升级时执行迁移脚本
  • 信件数据结构：mailbox → letter → pages → elements 四层嵌套
  • 计划组件数据独立存储，通过引用关联到信纸元素
  • 操作栈使用命令模式，每个操作封装为可撤销的Command对象

编辑器渲染

  • 信纸画布使用绝对定位元素方案，便于导出与交互
  • 拖拽使用 requestAnimationFrame 节流，保证60fps
  • 辅助线计算基于元素边界矩形，8px阈值吸附
  • 导出图片优先用 html2canvas，注意跨域图片处理
  • 竖排文字使用 writing-mode: vertical-rl，兼容测试
  • 真实信件材质用多层CSS背景叠加，减少图片资源依赖

音频系统

  • 录音优先 MediaRecorder API，格式根据浏览器自动选择
  • 维护全局音频管理器，统一控制BGM与录音的混音
  • 首次用户交互后解锁音频上下文，规避自动播放限制
  • 录音文件转 Blob 存入 IndexedDB，不存base64
  • 淡入淡出使用 GainNode 线性渐变，避免突兀

性能与体验

  • 信件画廊使用虚拟滚动，大量信件时保持流畅
  • 图片资源懒加载，优先加载可视区域内的缩略图
  • CSS动画优先使用 transform 和 opacity，触发GPU加速
  • IndexedDB操作封装为Promise，统一错误处理
  • 关键操作前检查存储容量，接近上限时提前提示
  • Service Worker 缓存静态资源，提升二次加载速度

核心原则：先可用，再好用，最后好玩

信笺的核心价值在于「书信的温度」。第一阶段先把创作和阅读的基础体验做扎实，让用户能安心写信、放心存信；第二阶段深化仪式感，让拆信读信成为值得期待的时刻；第三阶段打通慢递与手账，形成完整的情感闭环；最后用真实信件模板与个性化玩法拓展深度。

P0 基础可用
P1 体验流畅
P2 形成特色
P3 深度玩法
