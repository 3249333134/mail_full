# 信笺 UI 优化说明

## 输出内容

- `index.html`：可直接打开的高保真静态 UI 原型。
- `page-hierarchy.html`：按现有功能与操作逻辑整理的一级、二级、三级、四级页面设计矩阵。
- `next-step-design.html`：根据下一步优化清单设计的核心体验、操作逻辑和视觉风格方案。
- `real-letter-generator.html`：根据 p5-p8 参考图设计的真实信件生成器 UI。
- `styles.css`：设计稿样式，包含桌面与移动端响应式规则。
- `page-hierarchy.css`：全功能页面层级设计稿样式。
- `next-step-design.css`：下一步优化稿样式，强调旧纸、蜡封、语音气泡、慢递和移动端创作体验。
- `real-letter-generator.css`：真实信件模板样式，包含侨批封套、旧票据批信、竖排照片家书和桌面实物长信。
- 本稿保持现有项目的核心结构：`home-view`、`mailbox-view`、`editor-view`，并新增 `planner` 计划组件设计画板。

## 设计目标

1. 保留“信封、纸张、书信”的叙事气质，但减少单一米色带来的层级疲劳。
2. 从纯横向浏览改成更高效的管理界面：左侧信箱、中央主内容、右侧上下文信息。
3. 让信件详情页同时支持情绪化堆叠预览和清晰的阅读、编辑、导出、回信操作。
4. 编辑器改成稳定三栏：页面与工具、信纸画布、属性设置，降低当前工具区拥挤感。
5. 移动端不再强行横向展示复杂画廊，而是按单列重排，优先保证可读性和操作命中面积。
6. 根据讨论补齐编辑器产品能力：撤销重做、层级对齐、自动保存、备份导出、计划组件嵌入。
7. 把手账/日记/计划做成可插入信纸的组件，而不是只能独立打开的页面。

## 可迁移到现有代码的模块

- `css/main.css`
  - 可迁移侧边栏信箱项、信箱总览卡片、顶部操作区、信件详情右侧信息面板。
  - 建议把现有 `.gallery-main` 改成支持 `main-stage + context-panel` 的布局。

- `css/editor.css`
  - 可迁移新的三栏编辑器结构：`.tool-rail`、`.canvas-zone`、`.property-dock`。
  - 现有 `.toolbar` 和 `.property-panel` 可以渐进式替换，不需要一次性改 JS 逻辑。
  - 新增的 `.inline-planner-card`、`.dock-button-grid` 可用于信纸内嵌组件与属性面板能力补齐。

- `js/editor.js`
  - 需要补充撤销/重做栈、元素层级操作、对齐操作和组件内部编辑状态。
  - 自动保存建议 20-30 秒触发一次，并保留最近 5 个草稿版本。

- `js/journal.js`
  - 可承载年度/月/周/日计划组件的数据同步，作为信纸组件的共享数据源。

- `index.html`
  - 首页增加“正在阅读 / 快速继续”区块。
  - 信箱详情页增加当前信件信息面板。
  - 编辑器顶部增加预览、保存、缩放与适应画布操作区。

## 视觉规范

- 主文本：`#20232b`
- 次文本：`#687083`
- 主操作：深墨色 `#20232b`
- 叙事强调：玫瑰色 `#c95f7a`
- 支线功能：叶绿色 `#4d8a68`
- 夜色信箱：深蓝灰 `#283451`
- 卡片圆角：8px 到 14px，避免过度圆润。
- 大面积背景使用纸张白、浅灰绿和浅暖灰混合，避免只有棕色或米色。

## 交互建议

- 首页信箱卡片点击进入信箱详情；侧栏仅作为快速切换，不承担所有信息展示。
- 信箱详情页保留当前堆叠动画，但右侧固定展示当前信件的收信人、日期、状态和操作按钮。
- 编辑器中工具按钮保持固定尺寸，新增组件使用列表或网格，不让长文案撑开工具栏。
- 移动端优先展示当前信件与主要按钮，时间线和侧栏折叠到下方或抽屉。

## 本次追加的讨论落点

- **年度计划 3-in-1**：新增 `YEAR / NOTE / LIST` 标签结构，支持年度总览、自由笔记、清单页三类内容。
- **月/周/日计划**：在组件库中预留入口，后续可对应现有 `editor-widgets-month/week/daily` 模块。
- **信纸内嵌**：计划组件应该作为 `elements` 中的独立对象存储，保留位置、尺寸、透明度、内部数据和同步状态。
- **跨页面联动**：年计划点击月份可进入月计划，月计划日期进入日计划，任务状态在年/月/周/日/清单间同步。
- **编辑器补强**：属性面板加入置顶、置底、对齐、草稿备份，减少素材元素越多时的失控感。
- **数据安全**：增加自动保存状态与导出备份入口，避免刷新、关闭、移动端音频权限等场景造成体验中断。

## 全功能页面层级定义

- **一级页面**：用户进入某功能域的主入口，例如首页总览、信箱总览、手账入口、待寄入口。
- **二级页面**：具体功能区或列表视图，例如信箱详情、阅读器、年/月/日/模板视图、待寄列表。
- **三级页面**：核心任务执行页面，例如编辑器画布、样式选择、组件内部编辑、日记页面详情。
- **四级页面**：弹窗、设置、状态反馈和局部编辑，例如信箱主题设置、定时发送设置、录音权限、元素属性、备份导出。

## 当前项目功能覆盖

`page-hierarchy.html` 已按现有项目内容覆盖以下功能域：

- 全局工作台：信箱聚合、最近活动、搜索筛选、空状态。
- 信箱管理：默认信箱、自定义信箱、新增/编辑信箱、图标/主题/BGM。
- 信件创作：样式选择、编辑器、素材工具、组件库、草稿备份。
- 信件阅读：信封动画、阅读器、语音、回信、导出。
- 计划组件：年度/月/周/日/清单，作为信纸可嵌入组件。
- 日记支线：以撒的日记入口、47 页阅读、页码定位。
- 手账系统：年视图、月视图、日视图、模板视图和模板弹窗。
- 待寄信件：待寄列表、定时发送、状态变更、取消定时。
- 媒体与声音：BGM、录音、播放限制、权限与文件存储提示。

## 下一步 UI 与操作逻辑优化路线

优先实现顺序建议：

1. **先修核心短板**：录音自动播放改为语音气泡、编辑器撤销重做、层级对齐、自动草稿、备份恢复。
2. **再强化仪式感**：蜡封拆封、纸张音效、分页阅读、BGM/录音淡入淡出。
3. **补齐慢沟通体验**：双人信箱投递中、离线送达、随机慢递、信件投递包。
4. **打通内容闭环**：写信同步手账、日记目录书签、手账搜索、计划组件数据联动。
5. **降低学习成本**：首次引导、简洁模式、全局搜索、信件标签、移动端底部工具栏。
6. **最后处理扩展玩法**：自定义 BGM、个人印章、天气联动、节日彩蛋、模板包导入。

视觉方向：

- 参考“怀旧情书/旧相册”的情绪，而不是做成厚重复古页面。
- 大面积使用旧纸白、亚麻底、低饱和玫瑰色、茶绿色和墨色。
- 功能按钮尽量像从纸张边缘浮出的轻按钮，避免强工具软件感。
- 阅读和写作场景减少装饰卡片，保留纸张、信封、蜡封、照片和手写痕迹作为核心视觉信号。

## 真实信件生成器方向

基于用户提供的 p5-p8 参考图，并结合线上真实信件、侨批、航空邮简、电报、明信片、审阅邮件、古代书札和现代数字信件资料，新增 18 种“真实信件”设计方向：

- **01 竹简卷轴**：竹简外卷、木轴、竖排毛笔密信。
- **02 朱批奏折**：黄纸折页、朱批字、古代正式文书。
- **03 宋式花笺**：淡彩香囊封套、花笺、诗意手写。
- **04 黑金诏书**：黑底金字、封签、神秘庄重。
- **05 航空邮简**：红蓝斜纹边框、邮票区、路线标注、横线书写区。
- **06 电报急件**：编号、时间、加急标记、短句和机械打字感。
- **07 旅行明信片**：照片面与书写面分栏、邮资框、地址线。
- **08 战时审阅家书**：牛皮纸、折痕、审阅章和黑色遮挡线。
- **09 侨批封套**：红色中缝、黑色大字、收寄人竖排、批信封套堆叠。
- **10 旧票据批信**：红色表格线、凭证栏、旧纸斑驳、盖印效果。
- **11 竖排照片家书**：红线稿纸、竖排文字、老照片叠放、邮戳和花饰。
- **12 桌面实物长信**：桌面背景、钢笔墨水、照片、信纸叠层。
- **13 红柬请启**：红纸黑字、折页、请启/谨启章、礼仪性留白。
- **14 钢笔蓝墨信**：横线纸、私人信封、蓝黑墨水。
- **15 打字机公函**：牛皮纸公文袋、打字机正文、机密标签。
- **16 现代便利贴**：透明文件夹、便签、胶带、轻量留言。
- **17 邮件打印件**：办公室信封、打印邮件、二维码和回形针感。
- **18 赛博像素信**：霓虹边框、像素字体、数据封包。

字体方向：

- 真实信件模板已切换为毛笔/行楷优先字体栈：`STXingkai`、`华文行楷`、`KaiTi`、`楷体`、`FZKai-Z03S`、`Kaiti SC`、`HanziPen SC`。
- 钢笔模板使用更细的楷书/手写字体栈。
- 电报和打字机模板保留打字机字体栈。
- 赛博模板使用等宽像素感字体栈，和传统毛笔信形成强反差。

建议在真实项目里把它作为编辑器的“生成真实信件”能力：

1. 从当前信件读取正文、日期、收信人、照片、印章。
2. 用户选择 P5-P8 模板与真实化参数。
3. 系统自动排版为竖排/封套/票据/桌面长图。
4. 支持导出 PNG 长图、保存为信纸风格、生成信箱封面或投递包封面。
