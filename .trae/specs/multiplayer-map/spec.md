# 多人同屏互动 - Product Requirement Document

## Overview
- **Summary**: 将地图模式从单人+AI搭档模式改造为多人同屏实时互动模式。同一个共享信箱的成员可以在同一个地图中看到彼此，各自控制自己的角色，并能进行互动。
- **Purpose**: 让双人信箱的两个用户能在同一个地图世界里实时互动，增强沉浸感和社交体验。
- **Target Users**: 使用共享信箱的用户（如修璟和萱宣），在两台设备或两个浏览器窗口中同时在线。

## Goals
- 同一个共享信箱的成员角色同时出现在地图上
- 每个用户只控制自己的角色
- 角色位置、动作实时同步
- 角色之间可以互动（打招呼、做动作、双人互动等）
- 去掉原有的"双人模式"和"搭档角色"UI，改为多人同屏模式

## Non-Goals (Out of Scope)
- 不实现真正的网络通信（基于 localStorage + BroadcastChannel 实现本地多标签/窗口同步）
- 不实现语音/文字聊天
- 不实现复杂的物理碰撞和战斗系统
- 不支持超过4人同时在线
- 不实现服务器端同步（纯前端本地同步）

## Background & Context
- 当前地图模式有 player（自己）和 partner（AI搭档）两个角色
- 当前有"双人模式"（duetMode），播放预设的双人动作精灵图
- 已有共享信箱系统，支持多成员
- 已有用户认证系统，每个用户有对应的角色（修璟/xiu-jing，萱宣/xuan-xuan）
- 技术限制：纯前端应用，使用 localStorage 存储，可用 BroadcastChannel 实现同浏览器多标签通信

## Functional Requirements

### FR-1: 多人角色同屏显示
- 移除原有的"搭档角色"选择和"双人模式"UI
- 共享信箱的所有成员角色都显示在地图上
- 每个角色显示对应的人物外观（根据用户的 role 字段）
- 当前用户控制的角色有特殊标识（如名字高亮或光环）
- 其他用户的角色显示名字标签

### FR-2: 角色位置实时同步
- 当前用户的角色位置实时同步到共享状态
- 其他用户的角色位置从共享状态读取并渲染
- 同步频率：约 10-15 次/秒（流畅但不过于频繁）
- 使用 BroadcastChannel + localStorage 双重同步机制
- 角色移动平滑过渡（插值动画）

### FR-3: 角色动作同步
- 当前用户播放动作时同步给其他用户
- 其他用户的角色动作同步显示
- 支持的动作：移动（跑步/待机）、礼仪、武艺、招牌动作
- 动作播放状态同步（正在播放第几个动作、是否播放中）

### FR-4: 在线状态管理
- 进入地图模式时标记为"在线"
- 离开地图模式或关闭页面时标记为"离线"
- 心跳检测：超过 5 秒没有更新的角色判定为离线并淡出
- 离线角色不显示或半透明显示

### FR-5: 角色互动系统
- 靠近其他角色时显示互动提示
- 点击或按互动键（如空格）发起互动
- 互动类型：
  - 打招呼（挥手/行礼）
  - 双人动作选择（打开互动菜单）
  - 展示动作（触发自己的招牌动作）
- 互动请求需要对方确认（可选，简化版可自动接受）

### FR-6: 角色选择简化
- 登录用户只能使用自己对应的角色（修璟→修璟，萱宣→萱宣）
- 移除角色选择器中的分类和切换功能，改为显示当前角色信息
- 访客模式仍可自由切换角色（单人模式）

## Non-Functional Requirements
- **NFR-1**: 同步延迟 < 200ms（本地多标签场景）
- **NFR-2**: 角色移动平滑，无明显卡顿或跳变
- **NFR-3**: 页面刷新后能快速恢复状态
- **NFR-4**: 离线检测及时（5秒内）

## Constraints
- **技术**: 纯前端实现，使用 BroadcastChannel API + localStorage
- **依赖**: 现有用户认证系统、共享信箱系统、地图渲染器
- **平台**: 仅支持同一浏览器的多个标签/窗口（跨设备需要服务器，不在本期范围）
- **人数**: 最多支持 4 人同时在线

## Assumptions
- 用户在同一浏览器的两个窗口/标签中测试（模拟两个人）
- 使用 BroadcastChannel 进行实时通信，localStorage 作为持久化备份
- 每个用户的角色由其账号的 role 字段决定，不能自由切换
- 互动以动作为主，不需要复杂的游戏逻辑

## Acceptance Criteria

### AC-1: 多人角色同屏显示
- **Given**: 两个用户登录同一共享信箱的不同账号，并都进入地图模式
- **When**: 两个用户都在地图中
- **Then**: 每个用户都能看到对方的角色出现在地图上
- **Verification**: `programmatic`
- **Notes**: 两个浏览器窗口分别登录不同账号测试

### AC-2: 角色位置实时同步
- **Given**: 两个用户都在地图模式中
- **When**: 用户A移动自己的角色
- **Then**: 用户B的屏幕上，A的角色也随之移动
- **Verification**: `programmatic`
- **Notes**: 延迟应在可接受范围内

### AC-3: 角色动作同步
- **Given**: 两个用户都在地图模式中
- **When**: 用户A播放一个动作（如礼仪/武艺）
- **Then**: 用户B的屏幕上，A的角色也播放相同动作
- **Verification**: `programmatic`

### AC-4: 在线状态正确
- **Given**: 两个用户都在地图模式中
- **When**: 用户B关闭地图模式或关闭页面
- **Then**: 用户A的屏幕上，B的角色在5秒内淡出消失
- **Verification**: `programmatic`

### AC-5: 角色互动
- **Given**: 两个用户的角色靠近
- **When**: 用户A发起互动
- **Then**: 两个角色播放互动动作（如行礼、双人动作）
- **Verification**: `human-judgment`
- **Notes**: 互动动作可以是现有双人动作或简化版本

### AC-6: UI简化
- **Given**: 登录用户进入地图模式
- **When**: 查看角色控制面板
- **Then**: 不显示"搭档角色"和"双人模式"区域，只显示单人动作和当前角色信息
- **Verification**: `human-judgment`

### AC-7: 访客模式兼容
- **Given**: 访客（未登录）进入地图模式
- **When**: 查看角色控制面板
- **Then**: 仍可自由切换角色，行为与原来单人模式一致
- **Verification**: `programmatic`

## Open Questions
- [ ] 互动是否需要对方确认？（默认自动接受，简化实现）
- [ ] 最多支持几人同时在线？（默认4人）
- [ ] 角色名字标签是否一直显示？（默认一直显示）
- [ ] 是否需要碰撞检测（角色不能重叠）？（暂不需要，可穿透）
