# 游戏内对话气泡与信件系统 - 产品需求文档

## Overview
- **Summary**: 在多人游戏地图中添加实时对话气泡功能，玩家可在底部输入框输入文字，自己角色上方会显示气泡对话；同时支持将对话内容以信件形式发送到对方的共享信箱中，实现实时聊天与信件互通。
- **Purpose**: 增强多人游戏地图的社交互动体验，让玩家在地图中可以即时对话交流，并将重要对话以信件形式保存，实现"聊天即写信"的自然交互。
- **Target Users**: 多人模式下的游戏玩家（修璟、萱宣等共享信箱用户）

## Goals
- 玩家可通过底部输入框在地图中输入对话内容
- 输入发送后，自己角色上方显示聊天气泡
- 对方玩家屏幕上也同步显示对话气泡（多人同步）
- 对话内容自动以信件形式发送到对方的共享信箱
- 对方的信件会出现在自己的信箱列表中
- 气泡有淡出效果，显示一段时间后自动消失

## Non-Goals (Out of Scope)
- 不实现群聊/多人群发，仅一对一对话
- 不实现语音消息，仅文字对话
- 不实现消息撤回/删除功能
- 不实现表情图片发送，仅纯文本
- 不实现聊天记录持久化查看（只保留在信件中）
- 不实现已读/未读状态

## Background & Context
- 项目已有多人同步系统（MultiplayerSync），支持WebSocket/BroadcastChannel/localStorage三级降级
- 已有共享信箱系统（寒门信笺），修璟和萱宣可读写同一信箱的信件
- 已有游戏地图渲染器（GameMapRenderer），支持远程玩家渲染和交互系统
- 已有角色名字标签渲染系统，可在角色上方显示文字
- 用户提供的截图显示左侧有角色信息面板（萱宣/寒门），底部有输入框区域，地图中有角色

## Functional Requirements
- **FR-1**: 地图底部聊天输入框
  - 在游戏地图容器底部添加聊天输入框
  - 支持Enter键发送消息
  - 支持中文、英文、数字、标点符号输入
  - 有字数限制（最多50字）
  - 仅在多人模式下显示

- **FR-2**: 自己角色上方对话气泡
  - 发送消息后，自己角色上方显示气泡
  - 气泡样式：白色圆角背景，黑色文字，带小尾巴指向角色
  - 气泡位置：角色头顶上方，随角色移动
  - 气泡宽度自适应文字长度，最大宽度限制
  - 多行文字自动换行

- **FR-3**: 远程玩家对话气泡同步
  - 对方发送的消息通过多人同步系统实时接收
  - 在远程玩家角色上方显示对方的气泡
  - 气泡样式与自己的一致（或有细微区分，如背景色）
  - 多人同步延迟应在可接受范围内（<500ms）

- **FR-4**: 气泡自动消失与淡出动画
  - 气泡显示5秒后自动淡出
  - 淡出动画时长0.5秒
  - 新消息到达时重置旧消息的消失计时（最多同时显示1条）
  - 角色移动时气泡跟随移动

- **FR-5**: 对话内容自动生成信件
  - 每条发送的对话自动在共享信箱中生成一封简短信件
  - 信件标题：对话内容前10个字 + "..."
  - 信件内容：完整对话内容
  - 发件人标识：当前用户角色名（修璟/萱宣）
  - 收件人：对方角色
  - 信件类型标记为"对话信"（chat-letter）

- **FR-6**: 对方信件自动出现在自己信箱
  - 对方发送的对话信会自动出现在自己的共享信箱列表中
  - 基于现有的共享信箱机制（双方读写同一信箱）
  - 新信件到达时有提示（闪烁/红点）

- **FR-7**: 多人同步消息类型扩展
  - 在MultiplayerSync中新增chat消息类型
  - 消息包含：发送者ID、内容、时间戳
  - 支持WebSocket和BroadcastChannel两种通道

## Non-Functional Requirements
- **NFR-1**: 性能：气泡渲染不影响游戏帧率（保持60fps）
- **NFR-2**: 同步延迟：消息从发送到对方显示延迟<500ms（WebSocket模式）
- **NFR-3**: 兼容性：支持现有的三级降级同步策略（WebSocket→BroadcastChannel→localStorage）
- **NFR-4**: 样式一致性：气泡风格与现有游戏UI风格统一（复古/像素风）

## Constraints
- **技术**: 基于现有Vue2 + Canvas游戏地图架构，气泡用DOM元素渲染（与名字标签、交互提示一致）
- **业务**: 仅在多人模式且共享信箱模式下启用
- **依赖**: 依赖现有的MultiplayerSync、GameMapRenderer、STORAGE共享信箱系统

## Assumptions
- 用户已登录且处于共享信箱模式（寒门信笺）
- 多人同步系统已正常工作（WebSocket或BroadcastChannel）
- 共享信箱双方使用同一房间号
- 每条对话都是一封独立的简短信件

## Acceptance Criteria

### AC-1: 聊天输入框显示与交互
- **Given**: 用户已登录并进入多人地图模式
- **When**: 查看地图底部
- **Then**: 显示聊天输入框，点击可输入文字，按Enter发送
- **Verification**: `human-judgment`
- **Notes**: 输入框样式应与截图中底部白色边框区域一致

### AC-2: 自己角色上方气泡显示
- **Given**: 用户在聊天框输入文字并发送
- **When**: 消息发送成功
- **Then**: 自己角色头顶上方出现对话气泡，显示输入的内容
- **Verification**: `human-judgment`

### AC-3: 对方气泡同步显示
- **Given**: 两个玩家在同一房间的多人模式中
- **When**: 玩家A发送一条消息
- **Then**: 玩家B屏幕上玩家A的角色头顶显示该消息气泡
- **Verification**: `human-judgment`

### AC-4: 气泡自动消失
- **Given**: 角色上方显示着对话气泡
- **When**: 5秒内没有新消息
- **Then**: 气泡以淡出动画消失
- **Verification**: `human-judgment`

### AC-5: 对话自动生成信件
- **Given**: 用户在多人模式发送一条对话
- **When**: 消息发送成功后
- **Then**: 共享信箱中自动新增一封信件，内容为对话内容，发件人为当前用户
- **Verification**: `programmatic`
- **Notes**: 检查STORAGE.loadSharedLetters中是否新增了chat-letter类型的信件

### AC-6: 对方信件出现在自己信箱
- **Given**: 两个玩家在同一房间，玩家A发送一条对话
- **When**: 玩家B切换到信件模式查看共享信箱
- **Then**: 信箱列表中显示玩家A刚发送的对话信
- **Verification**: `programmatic`
- **Notes**: 基于共享信箱机制，双方读写同一数据

### AC-7: 气泡跟随角色移动
- **Given**: 角色头顶显示着气泡
- **When**: 角色移动
- **Then**: 气泡跟随角色同步移动，始终保持在头顶位置
- **Verification**: `human-judgment`

### AC-8: 字数限制
- **Given**: 用户在输入框输入文字
- **When**: 输入超过50个字符
- **Then**: 无法继续输入，或发送时截断并提示
- **Verification**: `programmatic`

### AC-9: 仅多人模式显示
- **Given**: 用户在单人模式下查看地图
- **When**: 查看地图底部
- **Then**: 不显示聊天输入框
- **Verification**: `human-judgment`

## Open Questions
- [ ] 信件是否需要特殊的"对话信"样式（如更短、更像便签），还是普通信件样式？
- [ ] 气泡最多同时显示几条？当前假设1条，新消息覆盖旧消息
- [ ] 是否需要发送按钮，还是只有Enter键发送？
- [ ] 对话信在信箱列表中是否需要特殊标记（如小图标）？
